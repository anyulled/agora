# ADR 0002: Browser DOM Capture and Native PDF Export

## Status
Accepted

## Date
2026-10-18

## Context
Agora provides slide-anchored PNG downloads for revealed slides, high-resolution slide thumbnails for the embedded Q&A slide, and a full compiled presentation PDF downloadable after the speaker reaches the ending slide.

Standard approaches often rely on server-side headless browsers (e.g. Puppeteer/Chromium running in AWS Lambda or Docker). In Cloudflare Workers or serverless edge environments, running Chromium is either technically impossible due to binary sandbox constraints or exorbitantly expensive and slow, requiring dedicated container infrastructure.

Furthermore, Reveal.js slides frequently contain rich CSS animations, custom fonts, vector graphics, code highlights, and CSS 3D transforms that server-side rasterizers often render inaccurately compared to how they appear in the presenter's actual browser.

## Decision
1. **Client-Side DOM Capture for Slide PNGs (`SlideRenderer`)**:
   - Slide PNGs are generated inside the administrator's browser via an off-screen sandbox DOM container.
   - The DOM node of each slide is captured in its **final visual state** (all fragments displayed, matching post-transition appearance).
   - Rendered using standard browser Canvas / SVG foreignObject rasterization encapsulated behind the `SlideRenderer` interface in `packages/slide-export`.
   - The resulting PNG Blobs are uploaded directly from the browser to the Cloudflare Worker `/api/v1/presentations/:id/assets` endpoint and stored in Cloudflare R2 tied to the presentation revision ID.

2. **Native Reveal.js Print-to-PDF Workflow**:
   - For full deck PDF generation, administrators leverage Reveal.js native PDF export stylesheet (`?print-pdf`).
   - Configured with `pdfSeparateFragments: false` to ensure single composite pages per slide.
   - The administrator saves the PDF via browser print-to-PDF and uploads it through the admin portal.
   - The uploaded PDF is versioned in Cloudflare R2 and tied to the presentation revision.

## Consequences
### Positive
- Zero server-side Chromium dependencies; completely eliminates container hosting costs and edge memory constraints.
- 100% visual fidelity: Slides are rendered using the exact same browser rendering engine and font rasterization as the live presentation.
- Decoupled export processing: Slide generation occurs during presentation authoring / staging, never during live presentation delivery.

### Negative / Trade-offs
- PDF export requires a manual browser print step by the administrator prior to publishing the presentation.
- If a presentation is edited after asset generation, stale assets must be invalidated and re-generated by the admin.
